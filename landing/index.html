Features

Everything you'd bolt on,
already bolted on.

One deploy, one database, no per-feature SaaS. Powered end-to-end by the Nano-GPT API.

01

Every model

All the frontier models through one key, with per-model provider selection and benchmark data from artificialanalysis.ai.

02

Images & video

Image generation with img2img, plus full video generation — inline, in the thread.

03

Search & scraping

Web Search and Deep Search built in. Paste a URL and the page is scraped into context automatically.

04

Memory that persists

Context memory per chat plus cross-conversation memory spanning every thread you own.

05

Voice in and out

Speech-to-text for dictation, text-to-speech for replies, YouTube transcripts on demand.

06

MCP servers

Connect Model Context Protocol servers and give your chat real tools to work with.

07

Projects & assistants

Group threads into projects, pick selectable system prompts, get generated follow-ups after every response.

08

Themes that fit

Configurable system themes, light and dark, tuned to feel like the client you'd have built.

09

Passkeys & API keys

Passkey login over HTTPS, plus a documented REST API so your scripts reach your instance.

Self-host

Clone it, fill in one env file.

Compose brings its own Postgres and wires DATABASE_URL for you. Data lives in ./data/postgres.

Docker recommended 
$ git clone https://github.com/nanogpt-community/nanochat
$ cd nanochat
$ cp .env.example .env
# fill in .env, then:
$ docker compose up
Bun for hacking on it 
# needs Postgres 14+ and Bun
$ cp .env.example .env
$ bun install
$ bun run db:migrate
$ bun run dev

In .env: set POSTGRES_PASSWORD, then generate BETTER_AUTH_SECRET and ENCRYPTION_KEY with openssl rand -base64 32. Not using Compose? Point DATABASE_URL at your own Postgres. Either way, the app comes up on localhost:3432.
